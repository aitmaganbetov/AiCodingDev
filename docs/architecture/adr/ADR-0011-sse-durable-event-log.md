# ADR-0011: SSE из durable `run_event_log`

- **Статус:** Proposed
- **Дата:** 2026-11-07

## Решение
1. Все события, видимые в UI по run, записываются outbox-диспетчером в `run_event_log(run_id, seq, event_id, …)`; `seq` — монотонный в пределах run (выдаётся под блокировкой строки-счётчика `runs.last_event_seq`).
2. SSE `id:` = `seq`. При переподключении с `Last-Event-ID: N` сервер отдаёт `seq > N` из таблицы, затем переключается на live. Дубли исключены по `seq`; клиент также дедуплицирует по `event_id` (AC-08).
3. Redis pub/sub канал `run:<id>` — только сигнал «есть новые события», не носитель данных.
4. Heartbeat каждые 15 с; проверка прав при подключении и не реже раз в 60 с (отзыв членства → закрытие потока).
5. `cli.output` — только sanitized выдержки ≤ 8 KiB на событие; полный raw-лог — защищённый artifact.

## Альтернативы
WebSocket — двунаправленность не нужна (команды идут REST с Idempotency-Key); SSE проще для прокси и Last-Event-ID.
