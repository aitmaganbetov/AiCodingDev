# ADR-0003: Только официальные Codex CLI и Claude Code CLI, авторизация по подпискам

- **Статус:** Accepted (ТЗ §1, §9, §22)
- **Дата:** 2026-11-07

## Контекст
ТЗ запрещает AI API, API keys, сторонних провайдеров, генеративные локальные LLM, обход лимитов подписок и неофициальную авторизацию. Внешние CLI меняются независимо от платформы.

## Решение
1. Единственные исполнители — **OpenAI Codex CLI** и **Anthropic Claude Code CLI**, установленные оператором из официальных источников.
2. Авторизация выполняется **человеком-оператором** штатной командой входа CLI на хосте/в томе учётных данных провайдера. Платформа никогда не читает, не копирует, не логирует и не хранит токены; в БД — только `auth_status` и ссылка на том/OS credential store.
3. **Runtime probe** при старте воркера и по запросу (`POST /providers/{id}/probe`): путь бинарника, версия, поддерживаемые режимы (noninteractive, машинный вывод, sandbox-режимы, resume), статус авторизации. Результат → `cli_installations.capabilities`, `provider_health`.
4. **Compatibility matrix** (`packages/cli_adapters/compat/*.yaml`): диапазоны версий → `command_profile` (argv-шаблоны) → парсер вывода. Неизвестная версия → `UNSUPPORTED_VERSION` (блокировка или ручное разрешение admin с аудитом).
5. Конкретные флаги CLI **не фиксируются в архитектуре**; кандидаты определяются и подтверждаются в Phase 2 тестами против реальных установок (opt-in suite).
6. Лимиты: `RATE_LIMITED` → cooldown провайдера; переключение на другой провайдер разрешено только как штатная маршрутизация, а не как обход лимита одной подписки (ни ротации аккаунтов, ни параллельных подписок для обхода).
7. Обычный CI использует `FakeCLIExecutor` с записанными (sanitized) фикстурами вывода.

## Альтернативы
Прямые API провайдеров — запрещено ТЗ. Эмуляция интерактивного TTY (expect/pty-скрейпинг) — только если официальный noninteractive режим отсутствует, и лишь после отдельного ADR; по умолчанию отвергнуто как хрупкое.

## Последствия
+ Соответствие лицензионным условиям и ТЗ.
− Зависимость от возможностей CLI (машинный вывод, usage) — данные о токенах могут быть `unknown`.
− **Риск RISK-01:** условия использования подписок для автоматизированного запуска должны быть подтверждены владельцем (OQ-01).
