# ADR-0009: Аутентификация веб-интерфейса

- **Статус:** Accepted (утверждено владельцем 2026-11-07)
- **Дата:** 2026-11-07

## Решение
1. v1.0: локальные учётные записи; пароль — argon2id (память ≥ 64 MiB, t=3, p=1 — уточняется бенчмарком на целевом железе), политика длины ≥ 12, проверка по локальному списку скомпрометированных паролей (офлайн).
2. Сессии на сервере (`user_sessions`, хранится только hash токена), cookie `aicd_session` (`Path=/api`): `HttpOnly`, `Secure`, `SameSite=Strict`, idle-timeout 30 мин, absolute 12 ч (значения API_DESIGN §3, настраиваемые), ротация при входе/повышении привилегий. *Уточнено в Phase 1: префикс `__Host-` несовместим с `Path=/api`.*
3. CSRF: double-submit — `X-CSRF-Token` заголовок для всех небезопасных методов + проверка `Origin`.
4. Блокировка на 15 мин после 5 неудачных попыток (API_DESIGN §3/§10), аудит входов (`auth.login`, `auth.login_failed`).
5. Первый запуск: bootstrap-команда CLI `aicd admin create-owner` (без дефолтных паролей).
6. OIDC (Keycloak/Authentik/GitHub OAuth) — опция P2, через тот же механизм сессий.
7. Machine-to-machine (локальный CLI платформы) — персональные токены доступа с ограниченным scope — P1 (OQ-04).

## Последствия
+ Работает офлайн, без внешнего IdP. − Ответственность за хранение паролей; MFA (TOTP) предлагается как P1.
